Evals are the bottom turtle, and drift keeps breaking them

Loops of agents checking agents still rest on verified, human-created eval data, and that layer is the hardest to build.

  • Valentine's answer to what firms underestimate was "hands down evals": defining success well enough to create ground truth is tedious and people hate doing it.
  • She borrowed the phrase "turtles all the way down" from an Arize developer: loops upon loops of agents, with evals at the bottom.
  • Sangani: stochastic apps drift. Data schemas, context, business rules and tool versions change, so a failing eval forces a triage between knowledge base, data quality, access or prompt.
  • Each fix raises a scope question: is the corrected truth global or true only for this use case, and which container holds it.
  • Zvibel: a year ago the obsession was hallucination; with reasoning models and good starting context it rarely appears now.
  • The new failure is nested agents answering from different understandings of context; each step is logical but the end result looks ridiculous to a human, so verify what every stage feeds the next.

A catalog is a map of what is, and ownership spans three roles

Agent-ready context is defined by the use case and the eval, and owned jointly by technical, functional and content people.

  • Sangani: a catalog describes what is; a messy catalog is a map of messy data, and agents need what ought to be.
  • Building "context" in isolation is the wrong target; you cannot know when you are done without a defined use case and eval.
  • Ownership in an agentic world needs a technical individual, a functional individual and a content owner: three people or thirty.
  • Zvibel: no enterprise project is truly AI-first since the mess predates agents; the realistic move is to modernize the data, with flash instead of hard drives for low latency.
  • Valentine's 2021 course research found the data-scientist and domain-expert relationship was the top predictor of effective ML; she now sees forward-deployed engineers filling that role for GenAI.
  • Her bank site hit about 99% agentic resolution; the workforce lacks expertise for the gnarly 1% and the bank is stuck on building trust across legal, HR and compliance to launch new use cases faster.

Storage after the warehouse: data lake, vector and graph

SQL and warehouses were designed for humans; panelists lean toward a lake with semantic search on top but admit the end state is unclear.

  • Sangani: religion about one architecture is damaging; he cited Iceberg table formats decoupling compute from storage and prefers "different horses for different courses".
  • Alation is releasing an ontology product built with agents; the promise is that users just declare intent and things happen.
  • Zvibel: SQL lets smart humans translate wishes into what a schema supports; he has a strong hunch that is not the AI-native way, and models hold far more context than one person.
  • His prediction: the industry returns toward a data lake on a vector store, with a small agent massaging the prompt and distilling results, though he has no "silver bullet" yet.
  • Q&A: a former JPMorgan data lead (now running a financial AI-workforce startup) suggested everything ends in a file system with vector search, citing LanceDB; Zvibel agreed storage ends up closer to a file system with semantic search, plus a graph.
  • The audience also raised temporal drift: an agent asked about yesterday at 10:00 must know that day's truth, not today's.

Agent-first companies and why security pulls inference in-house

Both vendors rebuilt themselves around agents, and credential propagation is pushing large enterprises to run their own stack.

  • WEKA started 13 years ago building a low-latency file system; early big customers in 2017 were GPU users, and the GPT moment turned a detour into the core business.
  • Zvibel: engineers used coding agents for a year-plus, then after a December-January inflection the whole company moved to AI; systems without an MCP get one built in-house.
  • WEKA embeds the equivalent of forward-deployed engineers; HR, finance and go-to-market now run hundreds of dashboards, agents and automated processes.
  • For sensitive data WEKA moved to its own GPUs, inference and internal MCPs, which controls who sees what and lets them open everything to AI.
  • Sangani: every data read or write will be intermediated by an agent, so Alation designed for agents first two years ago and bought Numbers Station, a Stanford-PhD team applying transformers to structured data.
  • Zvibel: user A's and user B's credentials must follow the whole nested agent chain, and a blanket-access API call to a cloud model doesn't work; this pushes large enterprises to bring infrastructure in-house.

What to do with this

Best Actionable Takeaways

🎯
Evals: Budget for human-built eval data first; treat agent-checks-agent loops as a layer on top of it.
🔄
Operations: Plan for drift: schemas, rules and tool versions change, so every failed eval needs a triage path to the right fix.
🧭
Data: Define context per use case and eval, not as a standalone catalog project.
👥
Org: Pair a technical owner, a functional owner and a content owner on every agentic process.
🔒
Security: Check that each user's credentials follow every nested agent call before opening data to agents.
💾
Infra: Stay architecture-agnostic on warehouse, lake, vector and graph; fit storage to the use case.

Names and terms at a glance

Glossary & Entities

Evals — Verified, typically human-created test data that defines what a correct agent output looks like.
Drift — Gradual change in data schemas, business rules, context or tool versions that breaks a previously working stochastic app.
Data catalog — A company-internal 'Wikipedia for data': an inventory describing the data an organization has.
Forward-deployed engineer (FDE) — A technical builder embedded with domain experts to gain enough business context to build a working system.
Iceberg table formats — Open table format that separates compute from storage, giving companies flexibility and sovereignty.
MCP — Model Context Protocol, the connector standard that lets agents reach internal systems.
